# CompilerLens 0.2.0

Historical release attempt: `v0.2.0` was tagged, but GitHub's wheel repair failed because
Ubuntu 22.04 supplied `patchelf 0.14.3`. That run did not reach PyPI publication.
The tag is retained unchanged; use [0.2.1](0.2.1.md) for the corrected release instructions.

## Highlights

- Shared ViT image-encoder and CLIP image/text-similarity adapters across CLI, Web Explore,
  Playground and source workflows, plus offline `tiny_vit` and `tiny_clip` demos.
- Modality-aware architecture views, observed tensor shapes and compiler-stage tracing.
- Pretrained ViT-Tiny and TinyCLIP validation with pinned revisions; ViT-Base also tested
  through Web Explore. Hugging Face repository URLs, revision pins and offline loading
  use the shared model-loading path.
- Float32 PyTorch-versus-compiled output verification for supported ViT/CLIP CPU captures.
- Native LLVM lineage in source workflows, a no-sudo Conda setup, and the Explore progress fix.
- Optional real-checkpoint compatibility workflow and stronger installed-wheel release checks.

## Historical installation target (use 0.2.1 instead)

On Linux x86-64 with glibc 2.35+ and Python 3.10:

```bash
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install compilerlens==0.2.0 --index-url https://pypi.org/simple/ \
  --extra-index-url https://download.pytorch.org/whl/cpu
python -m pip check
compilerlens doctor
compilerlens compile --example tiny_clip --out runs/tiny-clip --lineage required
compilerlens view runs/tiny-clip
```

The wheel bundles the browser app and native analyzer; users do not need Conda, Node,
CMake or an LLVM SDK. Use a fresh output directory for each capture.

## Scope and compatibility

- Existing CLI commands and saved-run compatibility are retained. Artifact schema remains
  0.7 and lineage sidecar schema remains 1; Python and native components report 0.2.0.
- ViT captures encoder states, not the classification head or pooler. CLIP captures image
  and text embeddings plus similarity logits, not caption generation.
- These paths use static batch-one CPU/float32 synthetic inputs. Real-image preprocessing,
  user captions, audio, encoder-decoder models and generation loops are not included.
- Web model loading retains the 100M-parameter limit. Compatibility is checkpoint-specific;
  see the [validated profiles](../CLI.md#validated-hf-checkpoints).
- Source/assembly attribution depends on emitted compiler locations. Missing locations
  remain unlinked; this is not a guarantee of complete cross-pass instruction identity.
