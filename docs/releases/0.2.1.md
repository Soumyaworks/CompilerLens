# CompilerLens 0.2.1

Release preparation: not yet tagged or published. This replaces the failed 0.2.0
publication attempt; the existing `v0.2.0` tag is retained unchanged.

## Changes

- Fix Linux wheel packaging by pinning `auditwheel==6.8.2` and `patchelf==0.19.1.0`.
  Ubuntu 22.04's `patchelf 0.14.3` is too old for the repair step and is no longer installed
  by the workflow. A preflight checks package versions and the actual executable on PATH.
- Build and smoke-test release wheels on branch pushes and PRs, before tagging.
  PyPI upload remains restricted to version-tag pushes and the `pypi` environment.
- Include the [0.2.0 feature set](0.2.0.md): ViT/CLIP adapters, offline vision demos,
  modality-aware architecture views, numerical checks, native lineage in source workflows
  and the no-sudo Conda setup. Runtime behavior is unchanged apart from version reporting.

## Install or upgrade after publication

Activate a Python 3.10 venv on Linux x86-64 with glibc 2.35+:

```bash
python -m pip install --upgrade compilerlens==0.2.1 \
  --index-url https://pypi.org/simple/ --extra-index-url https://download.pytorch.org/whl/cpu
python -m pip check
compilerlens --version
compilerlens doctor
compilerlens compile --example tiny_clip --out runs/tiny-clip --lineage required
compilerlens view runs/tiny-clip
```

Stop any running viewer before upgrading and restart it afterwards. Existing captures
are retained. Use a fresh output directory when compiling. End users do not need CMake,
LLVM, Node, `auditwheel` or `patchelf`; the wheel includes the app and native analyzer.

## Scope

ViT captures encoder states without the classifier/pooler. CLIP captures image/text
embeddings and similarity, not caption generation. These are static batch-one CPU/float32
synthetic-input workloads, not real-media preprocessing or quality evaluation. The web
parameter cap remains 100M. Artifact schema 0.7 and lineage schema 1 are unchanged.

## Validation and publication

Local checks passed on 30 September 2026: 48 tests, native/frontend builds, wheel repair
with the pinned packaging tools, metadata/platform checks, a clean dependency installation,
required-native matmul/vision-demo captures, pretrained ViT-Tiny CLI and TinyCLIP Web Explore,
numerical verification, assembly tracing and installed desktop/mobile browser checks.

See the [release checklist](../RELEASING.md) for local results and the exact commit/tag
sequence. The branch's full wheel-build job must pass before creating `v0.2.1`.
GitHub builds and verifies its own artifact; a local success does not guarantee future
network downloads, runner availability or PyPI permissions. Production verification remains
pending until the tagged workflow publishes and the PyPI download is tested.
